# ডেস্কটপ অ্যাপ ও অফলাইন গাইড (Unique POS)

এই ডকুমেন্টটি ডেস্কটপ (.exe) ভার্সন, অফলাইন মোড এবং হার্ডওয়্যার সেটআপের সম্পূর্ণ নির্দেশিকা।

---

## ১. এক নজরে — কী কী আছে

ডেস্কটপ অ্যাপটি তিনটি প্রসেস একসাথে চালায়, এবং সেগুলোই একটি সাধারণ ওয়েব ব্রাউজার উইন্ডোতে দেখানো হয়:

```
mongod (অ্যাপের সাথে বান্ডল করা)  →  Express API  →  Next.js  →  অ্যাপ উইন্ডো
        লোকাল ডেটাবেস               পোর্ট ৫০০০         পোর্ট ৩০০০     (ব্রাউজার লাগে না)
```

| বিষয় | অবস্থা |
|:---|:---|
| `.exe` ইনস্টল, ব্রাউজার লাগে না | ✅ অ্যাপের ভিতরেই Chromium আছে, `localhost` পেজ নিজেই খোলে |
| কাস্টমারের PC-তে Node.js লাগে কি? | ❌ লাগে না — অ্যাপ নিজের বাইনারিকে Node মোডে চালায় |
| অফলাইনে সম্পূর্ণ কাজ | ✅ লোকাল MongoDB সহ, ইন্টারনেট ছাড়াই সেল/স্টক/লেজার চলে |
| ক্লাউড সিংক | ✅ ইন্টারনেট ফিরলে Atlas-এ নিজে নিজে সিংক হয় |
| ESC/POS থার্মাল প্রিন্টার | ✅ আসল র-বাইট প্রিন্ট (Windows spooler RAW) |
| সাধারণ প্রিন্টার (A4 / Letter) | ✅ যেকোনো Windows প্রিন্টারে পুরো পেজের ইনভয়েস |
| ক্যাশ ড্রয়ার | ✅ প্রিন্টারের RJ11 দিয়ে kick pulse |
| বারকোড স্ক্যানার | ✅ USB HID — কিছু ইনস্টল করতে হয় না |
| ওয়েব + ডেস্কটপ দুই দিক | ✅ একই কোডবেস, আলাদা শুধু রানটাইম কনফিগ |

## ২. ডেভেলপমেন্টে চালানো

```bash
npm run install:all      # root + backend + frontend ডিপেন্ডেন্সি
npm run dev              # Electron শেল — ব্যাকএন্ড ও ফ্রন্টএন্ড নিজেই চালু করে
```

`npm run dev` অ্যাপটিকে `development` মোডে চালায়: ব্যাকএন্ড `ts-node-dev`-এ, ফ্রন্টএন্ড `next dev`-এ। এখানে পোর্ট বদলানো হয় না (ব্যাকএন্ড ৫০০০, ফ্রন্টএন্ড ৩০০০), কারণ dev-এ প্রক্সি টার্গেট ফিক্সড।

## ৩. ইনস্টলার (.exe) বানানো

```bash
npm run make:icon        # আইকন তৈরি (দরকার হলে একবার)
npm run fetch:mongod     # অফলাইন মোডের জন্য MongoDB বাইনারি নামায় (~৬৪ MB)

npm run dist             # পূর্ণ NSIS ইনস্টলার
# অথবা
npm run dist:dir         # দ্রুত টেস্টের জন্য আনপ্যাকড ফোল্ডার
```

`npm run dist` ভিতরে যা করে:

1. `npm run build:backend` — TypeScript কম্পাইল করে `backend/dist`
2. `npm run build:frontend` — `next build` (`output: 'standalone'`)
3. `node scripts/prepare-resources.js` — `build/` ফোল্ডারে রানটাইম ফাইল সাজায়
4. `electron-builder --win` — ইনস্টলার তৈরি করে `dist-electron/`

ফলাফল: `dist-electron/Unique POS Setup 1.0.0.exe`

### ইনস্টলারে কী কী যায়

`build/` ফোল্ডারটি `extraResources` দিয়ে অ্যাপের বাইরে (asar-এর বাইরে) কপি হয়, কারণ এগুলো আসল চাইল্ড প্রসেস হিসেবে চলে:

| ফোল্ডার | কী আছে | কেন asar-এর বাইরে |
|:---|:---|:---|
| `backend/` | `dist` + প্রোডাকশন `node_modules` + `uploads` | `node` দিয়ে স্পন করা হয়, asar থেকে চালানো যায় না |
| `frontend/` | Next.js `standalone` server + static + public | একই কারণ |
| `mongodb/` | `mongod.exe` | এক্সিকিউটেবল |
| `config/` | `app-config.json` টেমপ্লেট | প্রথম চালুতে userData-তে কপি হয় |

## ৪. রানটাইম কনফিগারেশন

সব সেটিং থাকে: `%APPDATA%\Unique POS\config.json`

প্রথমবার চালু হলে ইনস্টলারের টেমপ্লেট থেকে এটি তৈরি হয়।

| কী | অর্থ |
|:---|:---|
| `cloudMongoUri` | ক্লাউড (MongoDB Atlas) কানেকশন স্ট্রিং — সিংকের জন্য |
| `localMongoUri` | লোকাল ডেটাবেস (`mongodb://127.0.0.1:27017/pos_db`) |
| `localMongoPort` | mongod যে পোর্টে চলবে (ডিফল্ট ২৭০১৭) |
| `backendPort` / `frontendPort` | শুরু করার পোর্ট; ব্যস্ত থাকলে অ্যাপ নিজে পরের ফাঁকা পোর্ট নেয় |
| `jwtSecret` | প্রতি ইনস্টলে আলাদা করে তৈরি হয় (ইনস্টলারের ভিতরে থাকে না) |
| `syncEnabled` | ক্লাউড সিংক চালু/বন্ধ |
| `syncIntervalSeconds` | কত সেকেন্ড পর পর সিংক হবে |
| `hardware.printerName` | নির্দিষ্ট প্রিন্টার; খালি রাখলে Windows-এর ডিফল্ট প্রিন্টার |
| `hardware.paperWidth` | `58mm` বা `80mm` |

> ⚠️ **নিরাপত্তা:** কাস্টমারের মেশিনে দেওয়া কোনো credential আসলে গোপন থাকে না। `cloudMongoUri` ফাইল থেকে পড়া সম্ভব, তাই Atlas-এ এই অ্যাপের জন্য একটি **সীমিত অ্যাক্সেসের আলাদা ইউজার** বানিয়ে সেটিই ব্যবহার করবেন। আগের ভার্সনে পুরো `backend/.env` (পাসওয়ার্ড সহ) সরাসরি ইনস্টলারের ভিতরে যেত — এখন তা বন্ধ করা হয়েছে।

আগের ভার্সনের তুলনায় যা বদলেছে: JWT key আর শেয়ার হয় না, `.env` আর শিপ হয় না, আর পোর্ট ব্যস্ত থাকলে অ্যাপ নিজেই পরের পোর্টে চলে যায়।

## ৫. অফলাইন মোড কীভাবে কাজ করে

1. অ্যাপ চালু হলে Electron শেল বান্ডল করা `mongod.exe` চালায়:
   `--dbpath "%APPDATA%\Unique POS\db" --port 27017 --replSet rs0`
2. **replica set কেন?** সাধারণ (standalone) MongoDB মাল্টি-ডকুমেন্ট ট্রানজ্যাকশন চায় না। চেকআউট, রিটার্ন, wastage — সবই ACID ট্রানজ্যাকশনে চলে, তাই single-node replica set দরকার। ব্যাকএন্ড প্রথমবার নিজেই `rs.initiate()` করে নেয় (এতে প্রথম চালুতে ৩০-৪০ সেকেন্ড লাগতে পারে; দ্বিতীয়বার থেকে ২ সেকেন্ডের মধ্যে হয়)।
3. ইন্টারনেট না থাকলেও ব্যাকএন্ড লোকাল ডেটাবেসেই সব লেখে — সেল, স্টক, লেজার, শিফট।
4. ইন্টারনেট ফিরলে `SyncService` ক্লাউডের সাথে মিলিয়ে নেয়। প্রথম সিংকেই ক্লাউডের সব ডেটা (ইউজার, প্রোডাক্ট, কাস্টমার, সেটিংস) লোকালে নেমে আসে — তাই অফলাইনেও লগইন ও সেল কাজ করে।

**আগের সমস্যা যা ঠিক করা হয়েছে:** `connectDB` ফেল করলে `process.exit(1)` করত — মানে ইন্টারনেট গেলে পুরো অ্যাপ বন্ধ হয়ে যেত। এখন ব্যাকএন্ড ১৫ সেকেন্ড পর পর নিজে চেষ্টা করতে থাকে এবং ডেটাবেস ফিরলে নিজেই চালু হয়।

## ৬. সিংক নীতি (local ↔ cloud)

সিংক চলে টাইমস্ট্যাম্প কার্সরে: প্রতিটি মডেলে `updatedAt` (অপরিবর্তনীয় রেকর্ডে `createdAt`) আছে, তাই প্রতিবার জিজ্ঞেস করা হয় "শেষবারের পর কী কী বদলেছে"। `_id` দুই দিকেই একই থাকে, তাই একই রেকর্ড দুইবার তৈরি হয় না।

- **আগে push, পরে pull** — তাই সংঘর্ষ হলে লোকাল (দোকানের) কপি জেতে (last-write-wins)।
- **`both` (দুই দিক):** Product, Customer, Supplier, Sale, PurchaseOrder, Shift, Account, User, Role, Settings, Voucher, DailySalesSummary ইত্যাদি
- **`push` (শুধু উপরে যায়):** StockMovement, CustomerLedger, SupplierLedger, AccountTransaction, Expense, AuditLog
- **সিংক হয় না:** HoldCart (একটি টার্মিনালের সাময়িক কার্ট), TokenBlacklist, SyncState
- **Invoice নম্বর:** প্রতিদিনের কাউন্টার দুই দিকেই জেনারেট হতে পারে, তাই কাউন্টার দুটোকে সবসময় **বড়টি** ধরে মিলিয়ে নেওয়া হয় — একই ইনভয়েস নম্বর দুইবার ইস্যু হয় না।

সিংক স্টেটাস দেখা ও হাতে চালানো (admin/settings permission):

```
GET  /api/v1/sync/status     # কোন কালেকশন কতটা গেছে/এসেছে, শেষ রান, এরর
POST /api/v1/sync/run        # এখনই একবার সিংক চালাও
GET  /api/v1/health          # database: local|cloud, syncEnabled
```

**সীমাবদ্ধতা:** ডিলিট ইভেন্ট সিংকে যায় না (সিস্টেমে soft-delete ব্যবহার হয়, তাই প্রায় ক্ষেত্রেই সমস্যা নেই)। একই রেকর্ড একই সময়ে দুই জায়গায় বদলালে নতুনটি জেতে — পুরনোটি হারায়।

## ৭. হার্ডওয়্যার সেটআপ

### থার্মাল প্রিন্টার (ESC/POS)

1. Windows-এ প্রিন্টার ড্রাইভার ইনস্টল করে USB-তে লাগান (Generic/Text Only বা প্রস্তুতকারকের ড্রাইভার)।
2. ডেস্কটপ অ্যাপে **Settings → Receipt Printing (this computer)** খুলুন, **Thermal receipt printer** বেছে নিন, তারপর তালিকা থেকে প্রিন্টার ও কাগজের প্রস্থ (58mm/80mm) ঠিক করুন।
3. **Test print** চেপে যাচাই করুন — রিসিটে অ্যাপের নাম, সময় আর "ESC/POS ready" ছাপা উচিত।
4. POS-এ সেল সম্পন্ন করে **Print** চাপলে রিসিট সোজা প্রিন্টারে যায় (কোনো প্রিন্ট ডায়ালগ আসে না)।

সেটিংসটা `%APPDATA%\Unique POS\config.json`-এ `hardware.printerName` ও `hardware.paperWidth` হিসেবে জমা হয়, আর প্রিন্টার না বাছলে Windows-এর ডিফল্ট প্রিন্টার ব্যবহার হয়।

প্রিন্ট হয় কীভাবে: Electron main process ESC/POS বাইট তৈরি করে Windows spooler-এ `WritePrinter` (winspool.drv) দিয়ে RAW হিসেবে পাঠায়। কোনো নেটিভ নোড মডিউল লাগে না, তাই Electron আপডেটে ভাঙে না।

### সাধারণ প্রিন্টার (A4 / Letter)

থার্মাল রোল ছাড়া যেকোনো সাধারণ প্রিন্টারেও (লেজার/ইঙ্কজেট) রিসিট ছাপা যায় — পুরো একটা পেজের ইনভয়েস আকারে।

1. Windows-এ প্রিন্টারের ড্রাইভার ইনস্টল করে লাগান।
2. **Settings → Receipt Printing (this computer)**-এ **Normal printer (A4 / Letter)** বেছে নিন।
3. **Invoice printer** থেকে প্রিন্টার বাছুন (খালি রাখলে Windows-এর ডিফল্ট), **Paper size**-এ A4 বা Letter ঠিক করুন।
4. চাইলে **Show the Windows print dialog** চালু করুন — নাহলে থার্মাল প্রিন্টারের মতোই সোজা প্রিন্ট হবে, ডায়ালগ আসবে না।
5. **Test page** চেপে যাচাই করুন — একটা পূর্ণ পেজ ছাপা উচিত।

প্রিন্ট হয় কীভাবে: A4 প্রিন্টার ESC/POS বোঝে না, তাই অ্যাপ রিসিটটা একটা পূর্ণ পেজ (HTML) হিসেবে সাজায় এবং Chromium-এর মাধ্যমে সরাসরি Windows ড্রাইভারে পাঠায়। রিসিটে তখন দোকানের নাম-ঠিকানা, ইনভয়েস নম্বর, কাস্টমার, আইটেমের টেবিল আর হিসাবের খাতা — সব আলাদা করে সাজানো থাকে।

> **ক্যাশ ড্রয়ার:** ড্রয়ারটা প্রিন্টারের RJ11 পোর্টে লাগানো থাকে, তাই A4 মোডেও ড্রয়ার খুলতে একটা থার্মাল প্রিন্টার সেট করা লাগবে — সেকশনের নিচে "Cash drawer printer (thermal)" ঘরটা ঠিক ওই কাজেই।

### ক্যাশ ড্রয়ার

ড্রয়ারটি প্রিন্টারের RJ11 পোর্টে লাগানো থাকে, তাই খোলার কমান্ডটি (`ESC p 0 25 250`) একটি র-প্রিন্ট জব হিসেবেই যায়। নগদ পেমেন্টে চেকআউটের সময়ই ড্রয়ার খোলে (রিসিট প্রিন্টে দ্বিতীয়বার খোলে না)।

> ড্রয়ার না খুললে: প্রিন্টারের ড্রাইভার RAW ডেটা নিচ্ছে কি না দেখুন, এবং ড্রায়ারের তার প্রিন্টারের "DK" পোর্টে লাগানো আছে কি না নিশ্চিত করুন।

### বারকোড স্ক্যানার

USB স্ক্যানার কীবোর্ড হিসেবে টাইপ করে + Enter দেয় — কোনো সেটআপ লাগে না। POS পেজের বারকোড বক্স সবসময় অটো-ফোকাসে থাকে (F2 চাপলে আবার ফোকাস)। ওয়েব ভার্সনেও একইভাবে কাজ করে।

### ওয়েব ব্রাউজার থেকে হার্ডওয়্যার

যদি ওয়েব ভার্সন চালানো হয় ঠিক যে কম্পিউটারে প্রিন্টার লাগানো (রিমোট সার্ভার নয়), তাহলে ব্যাকএন্ড নিজেই প্রিন্টারে র-ডেটা পাঠায় — `POST /api/v1/hardware/print` ও `/hardware/cash-drawer` (লগইন করা ক্যাশিয়ার ছাড়া কাজ করে না)। রিমোট ব্রাউজারে কোনো র-প্রিন্ট পথ নেই, সেখানে অ্যাপ ব্যাকআপ হিসেবে ব্রাউজার প্রিন্ট ডায়ালগ খোলে।

## ৮. ডেটা কোথায় থাকে ও ব্যাকআপ

| কী | পথ |
|:---|:---|
| লোকাল ডেটাবেস | `%APPDATA%\Unique POS\db` |
| কনফিগ | `%APPDATA%\Unique POS\config.json` |
| অ্যাপের লগ | `%APPDATA%\Unique POS\logs\main.log` |
| mongod-এর লগ | `%APPDATA%\Unique POS\logs\mongod.log` |
| আপলোড (লোগো, ছবি) | ইনস্টল ফোল্ডারের `resources/backend/uploads` |
| ক্লাউড কপি | MongoDB Atlas (`cloudMongoUri`) |

**কিছু কাজ না করলে আগে `main.log` দেখুন** — অ্যাপের পুরো স্টার্টআপ (mongod, replica set, API, Next.js, সিংক) ওখানে ধাপে ধাপে লেখা থাকে। mongod-এর জার্নাল আলাদা ফাইলে যায়, তাই অ্যাপের লগ পড়ার মতো থাকে।

ব্যাকআপ: MongoDB-র `mongodump` বাইনারি বান্ডলে নেই, তাই ব্যাকআপের জন্য হয় অ্যাপের ভিতরের ব্যাকআপ টুল, নয়তো ডেটা ফোল্ডারের কপি, নয়তো Atlas ক্লাউড কপি ব্যবহার করুন। **আনইনস্টল করলে ডেটা মুছে যায় না** (`deleteAppDataOnUninstall: false`)।

## ৯. সমস্যা হলে

| লক্ষণ | কারণ ও সমাধান |
|:---|:---|
| "The POS API did not respond" | নির্দিষ্ট পোর্ট ব্যস্ত, বা ডেটাবেস শুরু হয়নি। অ্যাপ বন্ধ করে আবার খুলুন; `config.json`-এর পোর্ট বদলে দেখুন। |
| "The POS interface did not respond" | `resources/frontend/server.js` নেই — বিল্ড অসম্পূর্ণ। `npm run dist` আবার চালান (`npm run pack` অবশ্যই সফল হতে হবে)। |
| রিসিট প্রিন্ট হচ্ছে না | `hardware.printerName` খালি রাখলে ডিফল্ট প্রিন্টার ব্যবহৃত হয় — Windows-এ ডিফল্ট প্রিন্টার সেট করুন। এরর মেসেজ POS-এ দেখানো হয়। |
| ইনভয়েস নম্বর ডুপ্লিকেট | সিংক চলেনি। `POST /api/v1/sync/run` চালান, তারপর `GET /api/v1/sync/status`-এ `Counter` এরর আছে কি না দেখুন। |
| অ্যাপ দুবার খুলছে না | ইচ্ছাকৃত — একবারে একটি ইনস্ট্যান্স, নাহলে একই ডেটা ফাইল দুটি mongod খুলতে যেত। |
| অফলাইনে সেল হয় না | mongod বান্ডল হয়েছে কি না দেখুন (`resources/mongodb/bin/mongod.exe`)। না থাকলে `npm run fetch:mongod` দিয়ে আবার বিল্ড করুন। |
| বিল্ডে "app.asar is being used by another process" | `dist-electron\win-unpacked` ফোল্ডারে ঢুকে থাকা কোনো প্রসেস ফাইলটা ধরে রাখে, তাই electron-builder ফোল্ডারটা ফাঁকা করতে পারে না। সাধারণত তিনটি কারণ: (১) প্রজেক্ট OneDrive-এর `Documents`-এর ভিতরে থাকলে OneDrive ফাইলটা ধরে রাখে — প্রজেক্ট OneDrive-এর বাইরে সরান; (২) এডিটর/IDE (VS Code, Cursor, Command Code) ওয়ার্কস্পেস ইনডেক্স করার সময় `app.asar` খুলে রাখে; (৩) অ্যান্টিভাইরাস স্ক্যান। কোন প্রসেস ধরে আছে দেখতে Sysinternals-এর `handle64.exe -a app.asar` চালান (উইন্ডোজে এই টুলটি আগে থেকে থাকে না)। এডিটর/অ্যান্টিভাইরাস বন্ধ করে, অথবা `dist-electron` ফোল্ডার মুছে (রিস্টার্ট করে) আবার বিল্ড চালান। |
| বিল্ড "nsis-resources" নামানোর সময় আটকে থাকে | প্রথমবার NSIS ইনস্টলার বানানোর সময় electron-builder GitHub থেকে `nsis-resources` নামায়; ধীর বা ব্লকড নেটওয়ার্কে এটা আটকে যেতে পারে (কোনো এরর ছাড়াই ঝুলে থাকে)। নেটওয়ার্ক ঠিক থাকলে বিল্ড বন্ধ করে আবার চালান — একবার নামলে সেটি `%LOCALAPPDATA%\electron-builder\Cache`-এ ক্যাশে থাকে, পরেরবার আর লাগে না। |
| বিল্ডে winCodeSign symlink error | electron-builder-এর ক্যাশ extract করতে admin লাগে — একবার Developer Mode চালু করুন বা elevated terminal-এ বিল্ড চালান। |

## ১০. ওয়েব ভার্সন (Vercel) + ক্লাউড API

ওয়েব দিকটি আগের মতোই থাকে — বিস্তারিত `docs/DEPLOYMENT.md`-এ। মূল পার্থক্য:

- ওয়েব ভার্সন ক্লাউড ডেটাবেস ব্যবহার করে, তাই সেখানে অফলাইন নেই।
- ডেস্কটপ ভার্সন লোকাল ডেটাবেস ব্যবহার করে এবং ক্লাউডে সিংক করে — দুই দিকেই একই ডেটা দেখা যায়।
- দুই জায়গায় একই `_id` ব্যবহার হয়, তাই একই সেল/কাস্টমার দুইবার তৈরি হয় না।

API অরিজিন সর্বদা **same-origin প্রক্সি** দিয়ে যাওয়াই ভালো (`next.config.mjs`-এর rewrites): এতে `pos_token` কুকি first-party থাকে, আর ডেস্কটপ অ্যাপ ব্যাকএন্ডের জন্য যেকোনো ফাঁকা পোর্ট বেছে নিতে পারে।

## ১১. লাইসেন্স

ডেস্কটপ অ্যাপ **লাইসেন্স ছাড়া খোলে না**। কী না থাকলে বা মেয়াদ শেষ হলে ব্যাকএন্ড, ডেটাবেস বা POS উইন্ডো কিছুই শুরু হয় না — শুধু অ্যাক্টিভেশনের পর্দা আসে।

লাইসেন্স কী যাচাই হয় **অফলাইনেই** (Ed25519 সিগনেচার), তাই ইন্টারনেট বা কোনো সার্ভার লাগে না। কী-টি জমা থাকে `%APPDATA%\Unique POS\license.key` ফাইলে, তাই প্রতিবার অ্যাপ খুললে আর দিতে হয় না।

### গ্রাহকের জন্য

- অ্যাপ খুলে **Settings → License** খুললে দেখা যাবে: শপের নাম, সিরিয়াল, মেয়াদ কবে শেষ, আর কত দিন বাকি।
- **Machine ID** ওখানেই দেখা যায়, "Copy" বাটনে চেপে কপি করা যায় — নতুন কী নিতে হলে এই নম্বরটি পাঠাতে হয়।
- মেয়াদ শেষ হওয়ার আগেই **"Enter a new license key"** বাক্সে নতুন কী পেস্ট করে **Activate** চাপলে লাইসেন্স বদলে যায় — অ্যাপ বন্ধ করতে হয় না।
- মেয়াদ শেষের **১৫ দিন আগে থেকে** অ্যাপ খোলার সময় একবার করে মনে করিয়ে দেয় (দিনে একবারের বেশি নয়)।
- মেয়াদ শেষ হয়ে গেলে অ্যাপ আর খুলবে না; নতুন কী দিলেই **আগের সব ডেটা অক্ষত রেখে** আবার চালু হবে। সেল, স্টক, কাস্টমার লেজার — কিছুই মুছে যায় না।

### ডেভেলপারের জন্য

কী বানানো, চেক করা আর গ্রাহককে দেওয়ার নিয়ম বিস্তারিত আছে [`tools/license-generator/README.md`](../tools/license-generator/README.md)-এ। সংক্ষেপে:

```bash
npm run license:new     # নতুন কী বানাও
npm run license:check   # এই PC-র লাইসেন্স দেখো
```

> 🔐 `tools/license-generator/keys/private.pem` হলো মাস্টার চাবি — ব্যাকআপ রাখুন, কারো সাথে শেয়ার করবেন না, Git-এ কমিট করবেন না। হারালে পুরোনো ইনস্টল করা অ্যাপের জন্য আর কী বানানো যাবে না।
